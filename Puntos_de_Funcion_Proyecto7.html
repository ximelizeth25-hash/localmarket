1 Definiciones de los Componentes de Función

El análisis por Puntos de Función (FPA) cuantifica el tamaño de un sistema informático a partir de las funcionalidades que ofrece al usuario, independientemente de la tecnología implementada. Para el proyecto LocalMarket (Proyecto 7), se definen los cinco componentes estándar de la siguiente manera:

1. Entrada Externa (EI - External Input):
Procesos elementales en los que se reciben datos desde el exterior de la frontera del sistema para agregar, eliminar (física o lógicamente) o modificar datos en uno o más Archivos Lógicos Internos (ej. registrar usuario, publicar producto, anular pedido).
2. Salida Externa (EO - External Output):
Consultas o generación de informes emitidos al exterior que involucran cálculos derivados matemáticos, fórmulas de negocio, agregaciones porcentuales o actualización de estados (ej. balance financiero, ventas mensuales porcentuales, KPIs globales).
3. Petición Externa (EQ - External Inquiry):
Consultas o peticiones de información enviadas al exterior que no involucran cálculos derivados ni alteran archivos internos, limitándose a recuperar y presentar datos simples o filtrados (ej. catálogo público, lista de pedidos, libreta de domicilios).
4. Archivo Lógico Interno (ILF - Internal Logical File):
Grupo de datos lógicamente relacionados o información de control que es alterada directamente por el propio sistema (agregando, modificando o eliminando registros). Corresponde a las tablas maestras y transaccionales del proyecto en PostgreSQL.
5. Archivo de Interfaz Externa (EIF - External Interface File):
Grupo de datos lógicamente relacionados o de control que no son alterados por el sistema, sino únicamente consultados con fines de referencia. Son mantenidos por otro sistema externo ajeno a la aplicación (ej. pasarela de mensajería Wa.me/WhatsApp, catálogo postal SEPOMEX).

3 Puntos de Función Ajustados (PFA)

Para obtener el tamaño ajustado de la aplicación, se evalúan las 14 Características Generales del Sistema (GSC) propuestas por Albrecht. Cada factor se pondera en una escala de 0 a 5:

0: Sin influencia 1: Incidental 2: Moderado 3: Medio 4: Significativo 5: Esencial
Núm. Característica General del Sistema (GSC / Albrecht) Grado (0-5) Valor
1 ¿Requiere el sistema copias de seguridad y de recuperación fiables?
E-commerce transaccional con inventarios, ventas y pedidos que exige respaldos fiables con pg_dump y atomicidad.		 Significativo 4
2 ¿Se requieren comunicaciones de datos?
Arquitectura cliente-servidor web con llamadas REST API JSON y notificaciones WhatsApp externas.		 Significativo 4
3 ¿Existen funciones de procesamiento distribuido?
Distribución cliente (navegador SPA/Dashboard) y backend Node.js conectado a base de datos PostgreSQL.		 Medio 3
4 ¿Es crítico el rendimiento?
Respuestas en tiempo real en catálogo, compras directas y control de inventario con triggers.		 Significativo 4
5 ¿Será ejecutado el sistema en un entorno operativo fuertemente utilizado?
Servidor Node.js y motor PostgreSQL compartiendo recursos con múltiples clientes concurrentes.		 Medio 3
6 ¿Requiere el sistema entrada de datos interactiva?
Todos los módulos (productos, compras, usuarios, perfil, OTP) operan mediante formularios en vivo.		 Esencial 5
7 ¿Requiere entrada de datos interactiva que las transacciones se lleven a cabo sobre múltiples pantallas?
10 módulos diferenciados con navegación por pestañas, modales de stock bajo, filtros y edición en sitio.		 Significativo 4
8 ¿Se actualizan los archivos maestros de forma interactiva?
Los archivos maestros de usuarios, inventario de productos y pedidos se actualizan instantáneamente en línea.		 Esencial 5
9 ¿Son complejas las entradas, las salidas, los archivos o las peticiones?
Validaciones regex estrictas, control RBAC, triggers PL/pgSQL y generación de códigos OTP temporales.		 Medio 3
10 ¿Es complejo el procesamiento interno?
Procedimiento almacenado de venta atómica, bloqueo de seguridad tras 3 fallos y balance de utilidad.		 Medio 3
11 ¿Se ha diseñado el código para ser reutilizable?
Enrutadores modulares en Express, helpers de sanitización, vistas SQL y componentes frontend reutilizables.		 Significativo 4
12 ¿Están incluidas en el diseño la conversión y la instalación?
Scripts de migración automatizada de base de datos (BD.sql, objetos_bd.sql) incluidos para despliegue.		 Medio 3
13 ¿Se ha diseñado el sistema para soportar múltiples instalaciones en diferentes organizaciones?
Arquitectura SaaS parametrizable por roles adaptable a distintos comercios y mercados locales.		 Medio 3
14 ¿Se ha diseñado la aplicación para facilitar los cambios y para ser fácilmente utilizada por el usuario?
Interfaz intuitiva con Tailwind CSS, validaciones automáticas, alertas inmediatas y alta usabilidad.		 Esencial 5
Total Grados de Influencia ∑ Fi 50

Cálculo de la Ecuación de Puntos de Función Ajustados (PFA)

Fórmula de Albrecht / IFPUG:

PF = PFNA × [ 0.65 + 0.01 × ∑(Fi) ]

1. Factor de Ajuste de Complejidad (CAF):
CAF = 0.65 + 0.01 × 50 = 0.65 + 0.50 = 1.15

2. Puntos de Función Ajustados (PFA):
PF = 234 × 1.15 = 269.10 Puntos de Función

Resultado Final del Proyecto 7 (LocalMarket)
269.10 PFA
